# PICC 웹 계측 라벨링 툴

**AI와 전문의를 같은 test set에서 비교하기 위해, 전문의의 계측값과 소요시간을 모으는 도구.**

이 프로젝트 모델의 논문에서 증명하려는 것은 둘이다.

| | 가설 | 필요한 데이터 | 내보내기 열 |
|---|---|---|---|
| 1 | **정확도** — AI는 전문의보다 열등하지 않다 (non-inferiority) | 전문의 계측값 (mm) | `value_mm` |
| 2 | **속도** — AI는 전문의보다 빠르다 (superiority) | 전문의 계측 소요시간 | `duration_ms` |

그래서 이 도구가 정확해야 하는 것도 둘 — **mm 계측값**과 **소요시간**이다.
둘 중 하나라도 흔들리면 비교가 성립하지 않는다.

전문의를 2인 이상 두는 이유는 기준값을 만들기 위해서만이 아니다.
**사람끼리의 차이(`spread_mm`)가 AI 오차를 판단하는 잣대**가 된다 —
전문의 둘이 3 mm 다르게 재는 항목에서 AI가 3 mm 벗어난 것은 다른 의미다.

---

## 1. 계측 방식 — 문제 하나 = (영상 × 항목) 하나

영상 한 장을 띄워 놓고 8개를 몰아서 재지 않는다. **한 문제에 한 항목만** 잰다.

```
  브리핑         무엇을 잴지만 보여 준다. 사진은 아직 없다
                 (전체 화면 · 정의 + 두 점 위치 + 놓치기 쉬운 지점 + 논문 원문)
      ↓
  '측정 시작'    ← 여기서 시간 측정 시작. 사진이 나타난다
      ↓
  드래그 한 번   시작점에서 끝점까지
      ↓
  손을 뗀 순간   ← 여기서 시간 측정 종료
      ↓
  확인 팝업      계측선을 가리지 않는 쪽에 뜬다
      ├─ 확정              저장하고 바로 다음 문제
      ├─ 재측정 요청        대기 목록으로 되돌리고 바로 다음 문제
      └─ 확정 후 평가 종료   저장하고 중단. 다시 들어오면 남은 문제부터
```

이렇게 나눈 이유:

- **문제를 읽는 시간이 빠진다.** 무엇을 잴지 파악하는 시간은 '측정 시작' 전에 끝난다.
  그래서 브리핑 화면은 면적을 아끼지 않는다 — 정의를 덜 읽어서 생기는 편차가
  그대로 `spread_mm` 으로 들어오기 때문이다.
- **확정을 고민하는 시간도 빠진다.** 타이머는 손을 뗀 순간 멈춘다.
- 남는 것은 **영상을 보고 두 점을 찍는 시간**뿐이다. AI 추론 시간과 맞대어 볼 구간이 이것이다.

**여덟 항목 모두 드래그 한 번 = 두 점**으로 잰다. Rt.CL·Lt.CL·2VBUs도 마찬가지다.
재는 방식이 항목마다 다르면 소요시간을 서로 비교할 수 없다.

> 길이 = 두 점 사이의 직선거리. 이는 추론 코드와 같은 규칙이다 —
> `calculate_clavicle_length`는 keypoints[0]↔[4], `calculate_two_vbu_length`는
> 유효 점의 첫↔끝을 쓴다. 그래서 사람 값과 모델 값을 그대로 빼서 비교할 수 있다.

### 출제 순서는 완전 무작위

미계측 (영상 × 항목) 쌍 전체에서 무작위로 하나씩 낸다.
같은 영상의 8개를 연달아 내면 앞서 찍은 점을 기억한 채 다음 계측을 하게 되고
(anchoring), 소요시간도 두 번째부터 짧아진다. 둘 다 논문 지표를 오염시킨다.

### 재측정 요청

잘못 쟀다고 판단하면 **재측정 요청**을 누른다. 그 자리에서 다시 재지 않고
대기 목록으로 돌려보낸 뒤 다음 문제로 넘어간다 —
방금 본 화면을 기억한 채 다시 재면 편향이 생기기 때문이다.
나중에 무작위 순서로 다시 출제된다.

버려진 시도도 지우지 않는다. `status='redo'`로 남아 집계에서만 빠진다 —
몇 번 만에 만족했는지가 그 자체로 자료다.

## 2. 계측 항목 8개

모든 영상이 8개 항목 전부의 대상이다. 업로드 시 그룹을 나누지 않는다.

| key | 표시명 | 공식 계수 | 안내 그림 |
|---|---|---|---|
| `right_clavicle` | Rt. Clavicle | −0.062 | `Lt_cCL.png` |
| `left_clavicle` | Lt. Clavicle | −0.062 | `Rt_cCL.png` |
| `right_hvd` | Rt. HVD | +0.720 | `Rt_HVD.png` |
| `left_hvd` | Lt. HVD | +0.720 | `Lt_HVD.png` |
| `right_tcd` | Rt. TCD | +0.761 | `Rt_TCD.png` |
| `left_tcd` | Lt. TCD | +0.761 | `Lt_TCD.png` |
| `second_ribs_width` | 2nd Ribs Width | +0.255 | `Rt_2RHD.png` |
| `two_vbu` | Two VBUs | +1.024 | `2VBU_schematic.svg` ⚠️ (아래) |

안내 그림은 구 수동 계산기(`old_calculator/graphic/`)가 입력 포커스에 따라 띄우던 그림이다.
파일명의 `Rt_`/`Lt_`는 **접근 방향** 기준이라 해부학적 좌우와 반대인 경우가 있다 —
`Rt_cCL.png`는 '우측 접근의 반대측 쇄골' = **좌측 쇄골** 그림이므로 `left_clavicle`에 붙였다.

정의는 `app/variables.py` 한 곳에만 있다.

### 브리핑 화면에 무엇이 뜨는가

각 항목마다 `app/variables.py`가 다섯 가지를 들고 있고, 브리핑 화면이 그대로 보여 준다.

| 필드 | 화면에서 |
|---|---|
| `instruction` | 큰 글씨 한 줄 요약 |
| `point_a` / `point_b` | **Point A** / **Point B** 배지가 붙은 두 줄 — 점을 정확히 어디에 두는가 |
| `AXIS_NOTE[axis]` | 파란 상자 「측정 방향」 — 수평·수직 항목에만 (아래) |
| `caution` | 노란 상자 「놓치기 쉬운 지점」 |
| `paper_en` | 논문 원문 정의를 **병기**(기본 펼침, 접을 수 있음) |
| `axis` | `환자 장축에 직각` / `환자 장축 방향` / `두 점을 잇습니다` 배지 |

**두 점의 순서는 규정하지 않는다.** 길이는 첫↔끝 직선거리라 대칭이고
(`geometry.pixel_length`), 모델도 점 순서를 무시하도록 학습돼 있다. 그래서
'시작점/끝점'이 아니라 Point A / Point B 로 띄우고, 화면에도 "순서는 상관없습니다"
라고 적어 둔다.

안내문 안에서 `[[...]]` 로 감싼 부분은 화면에서 **노란 형광 강조**로 표시된다.
정의의 급소만 감쌀 것 — 다 강조하면 아무것도 강조되지 않는다. 지금 강조된 것들:

- **쇄골** — 끝의 경계선이 아니라 그 **중간점**
- **2RHD** — 바깥이 아니라 **내연(inner edge)**
- **TCD** — 장측 흉막이 아니라 **늑골 내연을 이은 선**(벽측 흉막), 기관 융기 **하연** 높이
- **HVD** — **최단 수평**거리
- **2VBU** — **추간판이 두 번** 들어감 (아래)

### ⚠️ 2VBU — 구 안내 그림이 추간판을 하나만 포함한다

`old_calculator/graphic/Rt_2VBU.png` 와 `Lt_2VBU.png` 는 **둘 다** 화살표가
**위 척추체의 상연에서 시작해 아래 척추체의 하연에서 끝난다** —
척추체 2개 + 추간판 **1개**다. 논문 정의(상연 → 두 칸 아래 상연)보다 **한 디스크 짧다.**

```
논문 정의    척추체 ① → 추간판 ① → 척추체 ② → 추간판 ②     (척추체 2 + 추간판 2)
구 그림      척추체 ① → 추간판 ① → 척추체 ②                (척추체 2 + 추간판 1)
```

실제로 계측자들이 추간판을 하나만 포함하는 실수를 반복했고, 그림을 그대로
따라간 결과로 보인다. 그래서 2VBU의 안내 그림을 교정 모식도
`static/graphic/2VBU_schematic.svg` 로 **교체했다** — 척추체 ①②③과 추간판 ①②를
그리고, Point A/B 위치와 '흔한 실수(척추체 ②의 하연에서 멈춤)'를 함께 표시한다.
원본 PNG는 지우지 않고 남겨 두었다(현재 미사용).

> **확인 완료 (연구책임자)** — 원 논문과 후속 논문, 그리고 **현재 학습된 모델까지
> 전부 추간판 2개**로 계측했다. 즉 데이터·계수 쪽에는 문제가 없고,
> **그림만 잘못 그려진 것**이다. 사람과 AI가 같은 규칙(추간판 2개)을 쓰므로
> 그대로 비교하면 된다.

> ⚠️ **남은 문제 — 구 수동 계산기** : `old_calculator/picc_app.py` 는 VBU 입력칸에
> 포커스가 가면 이 잘못된 그림을 띄운다(`Rt_2VBU.png` / `Lt_2VBU.png`).
> 배포본 `picc_app_beta.exe` 와 Qt 리소스 `picc_app_rc.py` 에도 그대로 들어가 있다.
> 그 계산기를 쓰는 사람은 지금도 한 디스크 짧게 잰 값을 넣게 된다.

### 수평·수직은 **영상이 아니라 환자** 기준이다

논문의 *horizontal* / *vertical* 은 픽셀 격자 방향이 아니라 환자의 방향이다.

- 환자의 장축(long axis) = 머리–발 방향.
- 이 데이터는 응급실·중환자실 **침상 이동형** 촬영이라 환자가 기울거나 회전한 채
  찍힌 영상이 흔하다. 그때 영상의 가로줄(같은 y)을 따라 재면 환자의 횡단면이
  아닌 사선을 재게 된다.
- 그래서 2RHD·HVD·TCD는 **환자 장축에 직각**으로, 2VBU는 **장축을 따라** 잰다.
  환자가 영상에서 10° 기울어 보이면 계측선도 10° 기운다.
- TCD의 "at the level of the carina inferior border" 에서 말하는 **'높이'도**
  기관 융기 하연을 지나면서 장축에 직각인 선이지, 수평 픽셀 행이 아니다.

**장축을 잡는 랜드마크는 일부러 못박지 않았다.** scoliosis 처럼 척추가 휘어
있으면 '척추체 중심선' 같은 기계적 기준이 오히려 틀리고, 머리–골반 중심을 이어야
하나 싶을 만큼 주관적이 된다. 원칙만 주고 판단은 계측자에게 맡긴다
(`AXIS_NOTE`, `app/variables.py`).

> 이 기준이라면 도구가 쓰는 **직선거리(`math.hypot`)가 곧 옳은 값**이다 —
> 계측선을 장축에 직각으로 그었다면 그 두 점 사이 거리가 바로 구하려는 횡단
> 거리다. 영상 기준으로 '수평 스냅'을 걸면 오히려 오차가 생기므로 넣지 않았다.

## 3. 빠른 시작

Python 3.12 기준이다.

```bash
python -m venv .venv
. .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env            # 초기 관리자 비밀번호를 반드시 바꿔 넣는다
python -m uvicorn app.main:app --host 127.0.0.1 --port 1531
```

접속: `http://127.0.0.1:1531`. 같은 LAN 의 다른 PC 에서 쓰려면 `--host 0.0.0.0`
으로 띄우고 방화벽 인바운드를 연다.

초기 관리자 계정은 `.env` 의 `INITIAL_ADMIN_USERNAME` / `INITIAL_ADMIN_PASSWORD`
이고, 관리자 계정이 하나도 없을 때만 생성된다. **첫 로그인 시 비밀번호 변경이
강제된다.**

`scripts/serve.py` 는 `app/**/*.py` 를 지켜보다 바뀌면 uvicorn 자식을 다시 띄우는
감시자다. Windows 에서 uvicorn 의 `--reload` 가 쓸 수 없어서 만든 것이다
(워커에게 보내는 `CTRL_C_EVENT` 가 특정 PID 로 가지 않아 `join()` 이 무한 대기한다).
Linux/macOS 에서는 `--reload` 를 그냥 쓰면 된다.

## 4. 운영 순서

1. **사용자** — 전문의 계정을 `계측자` 역할로 만든다. 임시 비밀번호는 화면에 한 번만
   표시되므로 그때 전달한다. **관리자는 계측에 참여할 수 없다**(일치도 집계 오염 방지).
2. **설정** — 불일치 판정 기준(mm)을 정한다. 기본 5 mm.
3. **업로드** — DICOM을 여러 개 한꺼번에 올린다(.zip 묶음도 가능).
   올린 영상은 자동으로 8개 항목 전부의 대상이 된다.
   영상 1장 = 계측자 1인당 문제 8개.
4. **계측** — 전문의가 각자 로그인해 문제를 푼다.
5. **매트릭스 / 불일치** — 허용범위를 넘은 항목을 확인한다 (읽기 전용).
6. **내보내기** — 분석용 파일을 받는다.
7. **AI 값과 대조** — 같은 test set에 모델을 돌려 예측값과 항목별 추론 시간을 뽑고,
   `measurements_long.csv`와 `image_id`·`variable`로 붙여 비교한다.
   **추론 쪽 픽셀 스페이싱 폴백을 고친 뒤에** 돌려야 한다(→ 7절).

## 5. 계측 화면 조작

| 조작 | 동작 |
|---|---|
| `Space` / `Enter` | **측정 시작** — 사진 공개 + 타이머 시작 (브리핑 화면에서) |
| **좌클릭 드래그** | 계측 — 시작점 → 끝점. 손을 떼면 완료 |
| **Shift + 좌클릭 드래그** | 화면 이동 (pan) |
| **우클릭 드래그** | 창 조절 — 좌우: 대비(WW), 상하: 밝기(WC) |
| 휠 | 커서 기준 확대/축소 |
| `Tab` | 샤프닝 3단계 순환 (OFF → 1 → 2 → 3, 아래 표) |
| `C` | CLAHE 강화 토글 |
| `W` | 창 조절 초기화 |
| `0` | 화면 맞춤 |
| `Enter` | 확정 (확인 팝업에서) |
| `R` | 재측정 요청 |
| `Esc` | 확정 후 평가 종료 |

**샤프닝 단계** — 언샤프 마스킹(반경/강도). 세기보다 **반경**이 체감을 좌우한다.
반경 1px는 2048px 영상에서 노이즈만 건드려 강도를 아무리 올려도 눈에 띄지 않는다.

| 단계 | 반경(px) | 강도 | 용도 |
|---|---|---|---|
| 1 | 2 | 1.2 | 미세 보정 |
| 2 | 5 | 2.4 | 일반 |
| 3 | 9 | 3.8 | 구조 탐색 |

⚠️ 3단계는 뼈 경계에 **헤일로(흰 테두리)** 가 생긴다(포화 픽셀 ~3.2%).
헤일로 바깥선을 경계로 착각하면 계측이 커진다. **끝점을 찍는 순간에는 1~2단계**를 권한다.
러닝 섬 박스 블러라 반경이 커져도 속도는 같고, 단계별 결과는 캐시된다.

**창 조절 방향** — 방사선과 뷰어 관례를 따랐다.
오른쪽으로 끌면 대비가 세지고, 왼쪽으로 끌면 약해진다.
위로 올리면 어두워지고, 아래로 내리면 밝아진다.
현재 값은 툴바에 `WW · WC` 로 표시된다.

- 확인 팝업은 **항상 우측 하단**에 뜬다.
- 8px 미만의 짧은 드래그는 오조작으로 보고 무시한다(시간은 계속 흐른다).
- 우측 **완료 목록**에 계측이 쌓인다. 항목을 누르면 다시 볼 수 있고, 거기서도
  재측정을 요청할 수 있다.

### 사진은 미리 받아 둔다

공개 순간에 네트워크를 타면 그 지연이 소요시간에 섞인다. 그래서 문제 카드를
띄우는 동안 이미지를 미리 받아 두고, 다 받기 전까지 `측정 시작` 버튼을
비활성화한다(`영상 준비 중…`). 다음 문제의 이미지도 현재 문제를 푸는 동안 미리 받는다.

`t0`는 그려진 프레임에서 찍되, 폴백을 먼저 박아 둔다 —
백그라운드 탭처럼 `requestAnimationFrame`이 늦게 뜨는 상황에서
소요시간이 통째로 사라지면 안 되기 때문이다.

## 6. 무조작 잠금

**60초** 동안 조작이 없으면 화면을 잠근다. 안내에도 **10초** 더 반응이 없으면

새 문제부터** 시작한다 — 자리를 비운 채 흘러간 시간이 그 문제의 소요시간에
남으면 안 되기 때문이다. 잠금 시간은 설정에서 바꿀 수 있다.

소요시간 상한은 24시간으로 클램프한다(이상값 완화).

## 7. 픽셀 스페이싱 — 가설 1의 급소

정확도 비교는 mm 단위로 이뤄지므로, 픽셀 스페이싱이 틀리면
**사람도 AI도 아닌 단위 환산이 오차를 만든다.**

좌표는 **DICOM 원본 픽셀**로 저장하고 mm는 그 좌표에서 계산한다 —
화면 확대율이나 렌더 해상도가 값에 끼어들 여지를 없앴다.

이 도구는 **`PixelSpacing`(0028,0030) → `ImagerPixelSpacing`(0018,1164) → 수동입력**
순으로 해석한다. Test set 519장 전수 조사 결과:

| 폴더 | n | `PixelSpacing` 없음 | `ImagerPixelSpacing` 없음 |
|---|---|---|---|
| Lt | 390 | **97 (24.9%)** | 0 (0%) |
| Rt | 129 | **26 (20.2%)** | 0 (0%) |

즉 약 23%가 `PixelSpacing`이 없지만 `ImagerPixelSpacing`은 전부 있다.
값도 0.14 / 0.1988 / 0.194222 / 0.187594 … 로 균일하지 않다.

> ⚠️ 기존 추론 코드(`picc_length_prediction_using_formula.py`, `picc_gui.py`)는
> `PixelSpacing`만 읽고 없으면 0.2 mm 또는 0.831 mm 고정값으로 떨어진다.
> GUI 경로는 환산조차 하지 않는다.
> **이 상태로 비교하면 모델이 실제보다 부정확해 보인다** —
> 오차의 상당 부분이 모델 성능이 아니라 단위 환산에서 나오기 때문이다.
> AI 예측값을 뽑기 전에 추론 쪽 폴백을 먼저 고쳐야 한다.

둘 다 없는 영상은 등재는 되지만 mm 계측이 불가하다. **설정** 화면에 목록이 뜨고,
값을 넣으면 그 영상의 기존 계측이 전부 다시 계산된다.

## 8. 불일치 판정 (interobserver agreement)

> **확정값(GT)은 만들지 않는다.** 이 연구는 계측자들의 값을 하나로 합의시키지 않는다.
> 각자의 계측이 그대로 분석 대상이고, 아래 판정은 **보고용 지표일 뿐** 계측값을
> 바꾸거나 버리거나 대체하지 않는다.

같은 (영상, 항목)에 대해 유효한(`status='done'`) 계측을 모아

```
n < 2                                  → 비교 불가(일부만 계측)
max(values) - min(values) > 허용범위    → 불일치
그 외                                   → 일치
```

매트릭스와 불일치 목록은 **읽기 전용**이다 — 어느 항목에서 계측자들이 얼마나
벌어졌는지 확인하는 화면이지, 값을 고르거나 확정하는 화면이 아니다.

허용범위를 바꾸면 표시만 즉시 재계산된다. 저장된 계측은 그대로다.
판정 결과는 저장하지 않는 파생값이라 언제든 기준을 바꿔 볼 수 있다.

관리자 대시보드의 **`2인 이상이 잰 (영상×항목)`** 이 실질 진척도다 —
AI와 맞대어 볼 수 있는 항목이 몇 개인가를 뜻한다.

## 9. 내보내기

| 파일 | 용도 |
|---|---|
| `measurements_wide.xlsx` | 행=영상. 계측자별 8개 값·항목별 소요시간·계측자 간 차이를 옆으로 펼침 |

| `disagreements.xlsx` | 허용범위 초과 항목만, 차이 큰 순 |
| `picc_data_bundle.zip` | 위 3종 + **계측자별** 좌표를 학습용 어노테이션 JSON으로 (`annotations/<계측자>/<항목>/`) |
| `picc_full_bundle.zip` | 위 전부 + 원본 DICOM + 렌더 PNG (용량 큼, 스트리밍) |

**두 가설이 어느 열에서 나오는가** (전부 `measurements_long.csv` 안에 있다)

| | 열 |
|---|---|
| 가설 1 · 정확도 | `value_mm` |
| 사람끼리의 변동폭 (판단 잣대) | `spread_mm` |
| 가설 2 · 속도 | `duration_ms` |
| AI와 맞댈 대상 | `gt_value_mm` |

`status='done'`만 유효하며 `'redo'`는 버려진 시도다 — 속도 분석에서 빼야 한다.

> **비교할 때 맞출 것** — 사람 쪽 `duration_ms`에는 영상을 보고 두 점을 찍는
> 시간이 들어 있다. AI 쪽도 같은 구간(DICOM 로드 → 검출 → 계측값 산출)으로 재야
> 공정하다. 모델 가중치 로딩 같은 1회성 비용은 빼거나 따로 보고한다.

어노테이션 JSON은 기존 학습 포맷과 같다 —
`data/annotations/<항목>/<파일명>_<항목>.json`, clavicle/two_vbu는 `points`,
hvd/tcd/2nd ribs는 `line` 키. (계측은 전부 두 점이지만 기존 포맷을 그대로 따랐다.)

고급 통계(ICC, Bland-Altman, 비열등성 검정)는 웹에 넣지 않았다.
long CSV를 R이나 SPSS로 가져가는 편이 논문 작성에 낫다 —
필요한 검정과 표기가 저널마다 다르기 때문이다.

## 13. 초기화 (관리자 화면)

테스트를 마치고 실전 데이터로 넘어갈 때 **관리자 › 초기화**에서 지운다.
되돌릴 수 없으므로 안전장치가 두 겹 있다 — **본인 계정 비밀번호**와
**확인 문구**를 둘 다 맞게 입력해야 실행되고, 하나라도 틀리면 아무것도 지우지 않는다.

| 범위 | 지우는 것 | 남는 것 | 확인 문구 |
|---|---|---|---|
| 계측 기록만 초기화 | 계측값 | 영상 · 계정 · 설정 | `계측 기록 삭제` |
| 영상까지 초기화 | 위 + 영상(DICOM/PNG 파일 포함) | 계정 · 설정 | `영상까지 삭제` |
| 전체 초기화 | 위 + 계측자 계정 · 설정 | 관리자 계정 | `전체 삭제` |

**관리자 계정은 어떤 범위에서도 지워지지 않는다** — 지우면 아무도 로그인할 수 없다.

**초기화 직전에 DB 전체가 자동으로 백업된다** — `data/backups/app_<시각>.db`.
실수로 지웠어도 그 파일을 `data/app.db` 로 되돌리면 복구된다(서버를 멈추고 교체).
확인 문구·비밀번호를 통과했더라도 스냅샷은 무조건 남는다.

## 14. 백업과 파일 단위 초기화

- **백업 대상**: `data/` 전체 (`app.db` + `dicom/` + `png/`) 와 `.env`.

  다음 기동 때 `.env`의 초기 관리자 계정이 다시 만들어진다.

## 15. 문제 해결

| 증상 | 확인 |
|---|---|
| 업로드가 전부 실패 | 현황 화면의 디코더 상태. `setup_venv.ps1` 재실행 |
| mm 값이 비어 있음 | 설정 화면의 '픽셀 스페이싱 미상' 목록. 수동 입력 |
| 확인 팝업에 '소요시간 기록 실패' | 브라우저가 백그라운드였거나 렌더러가 멈춘 경우. 해당 문제는 재측정 요청으로 되돌릴 것 |
| 다른 PC에서 접속 안 됨 | `.env`의 `WEBAPP_HOST=0.0.0.0` 확인, 방화벽 TCP 1531 인바운드 |
| 재부팅 후 서버 없음 | `schtasks /query /tn PICC-Labeling-Server /v /fo LIST`, `data/logs/launcher.log` |
| 포트 충돌 | `.env`의 `WEBAPP_PORT` 변경 후 `install_autostart.ps1` 재실행 |
| 서버가 안 죽음 | `stop_server.ps1`을 쓸 것. venv의 `python.exe`는 **베이스 인터프리터를 자식으로 띄우므로**, 실행 경로로 프로세스를 찾아 죽이면 껍데기만 죽고 서버는 살아남는다 |
| `stop_server.ps1` 이 Access denied | 예약 작업이 서버를 **SYSTEM 계정**으로 띄웠기 때문. PowerShell 을 **관리자 권한으로 실행**한 뒤 다시 돌린다. (스크립트가 이 경우를 감지해 안내하고 종료코드 1을 낸다) |
